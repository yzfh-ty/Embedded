# 数据同步函数详解

## 概述

在嵌入式Linux系统中，数据同步函数负责将内存中的缓冲数据刷新到持久化存储设备中。由于操作系统为了提高性能会使用缓存机制，数据可能暂时存储在内存缓冲区中而非立即写入磁盘。数据同步函数确保重要数据能够及时持久化，避免系统异常断电等情况下数据丢失。

## 数据同步函数族

```c
#include <unistd.h>
void sync(void);           // 同步所有缓冲区到磁盘
int fsync(int fd);         // 同步指定文件的内容和元数据
int fdatasync(int fd);     // 同步指定文件的数据（不包括元数据）
```

### 1. sync() 函数

#### 函数原型
```c
#include <unistd.h>
void sync(void);
```

#### 功能说明
- 触发系统范围内所有修改过的缓冲区数据写入磁盘
- 不等待写入操作完成就立即返回
- 影响所有挂载的文件系统

#### 使用场景
- 系统关机前的数据同步
- 定期批量同步所有缓存数据
- 系统维护操作

#### 示例代码
```c
#include <unistd.h>
#include <stdio.h>

int main() {
    // 执行一些文件操作
    FILE *fp = fopen("/tmp/test.txt", "w");
    if (fp) {
        fprintf(fp, "Important data\n");
        fclose(fp);
    }
  
    // 同步所有数据到磁盘
    sync();
    printf("All data synchronized to disk\n");
  
    return 0;
}
```

### 2. fsync() 函数

#### 函数原型
```c
#include <unistd.h>
int fsync(int fd);
```

#### 参数说明
- `fd`: 已打开文件的文件描述符

#### 返回值
- 成功：返回0
- 失败：返回-1，设置errno

#### 功能说明
- 强制将指定文件的所有数据和元数据同步到存储设备
- 等待同步操作完成才返回
- 包括文件内容、文件属性（大小、修改时间、权限等）

#### 错误码
- `EBADF`: fd不是有效的文件描述符
- `EIO`: I/O错误
- `EROFS`: 文件位于只读文件系统
- `EINVAL`: fd指向的不是普通文件

#### 示例代码
```c
#include <unistd.h>
#include <fcntl.h>
#include <stdio.h>
#include <errno.h>
#include <string.h>

int safe_write_file(const char *filename, const char *data) {
    int fd = open(filename, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) {
        perror("open");
        return -1;
    }
  
    ssize_t bytes_written = write(fd, data, strlen(data));
    if (bytes_written == -1) {
        perror("write");
        close(fd);
        return -1;
    }
  
    // 确保数据写入磁盘
    if (fsync(fd) == -1) {
        perror("fsync");
        close(fd);
        return -1;
    }
  
    printf("File synchronized successfully\n");
    close(fd);
    return 0;
}

int main() {
    safe_write_file("/tmp/important_data.txt", "Critical system data\n");
    return 0;
}
```

### 3. fdatasync() 函数

#### 函数原型
```c
#include <unistd.h>
int fdatasync(int fd);
```

#### 参数说明
- `fd`: 已打开文件的文件描述符

#### 返回值
- 成功：返回0
- 失败：返回-1，设置errno

#### 功能说明
- 只同步文件数据内容到存储设备
- 不强制同步文件元数据（如修改时间、访问时间等）
- 相比fsync性能更好，因为减少了同步的数据量
- 等待同步操作完成才返回

#### 性能对比
在只关心文件内容持久化的场景下，fdatasync比fsync快约30-50%，因为避免了元数据的同步开销。

#### 示例代码
```c
#include <unistd.h>
#include <fcntl.h>
#include <stdio.h>
#include <sys/stat.h>

// 高频日志写入场景
int write_log_entry(int log_fd, const char *message) {
    char buffer[256];
    time_t now = time(NULL);
    snprintf(buffer, sizeof(buffer), "[%ld] %s\n", now, message);
  
    if (write(log_fd, buffer, strlen(buffer)) == -1) {
        perror("write log");
        return -1;
    }
  
    // 只同步数据，不关心元数据，提高性能
    if (fdatasync(log_fd) == -1) {
        perror("fdatasync");
        return -1;
    }
  
    return 0;
}

int main() {
    int log_fd = open("/var/log/app.log", O_WRONLY | O_APPEND | O_CREAT, 0644);
    if (log_fd == -1) {
        perror("open log");
        return 1;
    }
  
    // 模拟高频日志写入
    for (int i = 0; i < 1000; i++) {
        char msg[64];
        snprintf(msg, sizeof(msg), "Log entry %d", i);
        write_log_entry(log_fd, msg);
    }
  
    close(log_fd);
    return 0;
}
```

## 函数区别详细对比

| 特性 | sync() | fsync(fd) | fdatasync(fd) |
|------|--------|-----------|---------------|
| 作用范围 | 系统全局 | 单个文件 | 单个文件 |
| 同步内容 | 所有缓冲数据 | 数据+元数据 | 仅数据 |
| 阻塞等待 | 否 | 是 | 是 |
| 性能 | 最慢 | 中等 | 最快 |
| 使用场景 | 系统级同步 | 关键数据持久化 | 高频数据写入 |

## 实际应用场景

### 1. 数据库存储引擎
```c
// 模拟数据库事务提交
int commit_transaction(int db_fd, const char *data) {
    // 写入事务数据
    write(db_fd, data, strlen(data));
  
    // 确保事务数据持久化
    if (fsync(db_fd) == -1) {
        return -1; // 事务提交失败
    }
  
    return 0; // 事务提交成功
}
```

### 2. 嵌入式设备配置保存
```c
// 配置文件安全写入
int save_config_safely(const char *config_path, const char *config_data) {
    char temp_path[256];
    snprintf(temp_path, sizeof(temp_path), "%s.tmp", config_path);
  
    int fd = open(temp_path, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) return -1;
  
    write(fd, config_data, strlen(config_data));
  
    // 确保配置数据写入磁盘
    if (fsync(fd) == -1) {
        close(fd);
        return -1;
    }
  
    close(fd);
  
    // 原子性重命名
    if (rename(temp_path, config_path) == -1) {
        return -1;
    }
  
    return 0;
}
```

### 3. 实时日志系统
```c
// 实时日志写入优化
typedef struct {
    int fd;
    size_t buffer_size;
    size_t buffer_pos;
    char *buffer;
} log_writer_t;

int log_writer_flush(log_writer_t *writer) {
    if (writer->buffer_pos == 0) return 0;
  
    ssize_t written = write(writer->fd, writer->buffer, writer->buffer_pos);
    if (written != (ssize_t)writer->buffer_pos) {
        return -1;
    }
  
    // 高频场景使用fdatasync优化性能
    if (fdatasync(writer->fd) == -1) {
        return -1;
    }
  
    writer->buffer_pos = 0;
    return 0;
}
```

## 性能优化建议

1. **选择合适的同步函数**：
   - 关键业务数据使用fsync确保完整性
   - 日志等高频写入使用fdatasync提升性能
   - 系统关机时使用sync进行全局同步

2. **减少同步频率**：
   ```c
   // 批量写入后同步，避免频繁同步
   for (int i = 0; i < 100; i++) {
       write(fd, data[i], len[i]);
   }
   fsync(fd); // 一次性同步
   ```

3. **异步同步处理**：
   ```c
   // 在单独线程中处理同步，避免阻塞主业务
   void* sync_thread(void* arg) {
       while (running) {
           sleep(30); // 每30秒同步一次
           sync();
       }
       return NULL;
   }
   ```

## 注意事项

1. **文件描述符有效性**：确保传入的fd是打开且有效的
2. **错误处理**：正确处理同步失败的情况
3. **性能权衡**：根据业务需求选择合适的同步级别
4. **存储介质特性**：考虑SSD、eMMC等不同存储介质的特性
5. **电源管理**：在嵌入式系统中考虑电源故障对数据持久化的影响
