# 文件锁机制详解

文件锁是多进程环境中保证数据一致性的重要机制。在 Linux 中，通过 `fcntl()` 系统调用来实现基于文件描述符的记录锁（record lock），即所谓的“文件锁”。

## 一、flock 结构体详解

### 1. 定义

```c
#include <fcntl.h>
#include <unistd.h>

struct flock {
    short  l_type;    /* 锁类型 */
    short  l_whence;  /* 偏移基准位置 */
    off_t  l_start;   /* 相对于 l_whence 的偏移量 */
    off_t  l_len;     /* 锁长度，0 表示到文件末尾 */
    pid_t  l_pid;     /* 拥有该锁的进程 ID（仅当使用 F_GETLK 查询时才会填充）*/
};
```

| 成员变量 | 描述 |
|----------|------|
| l_type   | 锁的类型：<br>`F_RDLCK`：共享读锁<br>`F_WRLCK`：独占写锁<br>`F_UNLCK`：解除锁 |
| l_whence | 参考点：<br>`SEEK_SET`：从文件开始计算<br>`SEEK_CUR`：从当前位置开始计算<br>`SEEK_END`：从文件结尾开始计算 |
| l_start  | 相对偏移（字节） |
| l_len    | 锁定区域的长度（字节），0 表示锁定直到文件结尾 |
| l_pid    | 锁持有者的进程 ID（查询使用） |

### 2. 锁的语义规则

多个进程可以同时获取同一段文件的读锁；
但写锁只能被一个进程持有，不允许其他任何读或写锁；

| 锁类型组合 | 结果 |
|------------|------|
| 读锁 + 读锁 | 允许 |
| 读锁 + 写锁 | 阻塞 |
| 写锁 + 读锁 | 阻塞 |
| 写锁 + 写锁 | 阻塞 |

## 二、常用宏定义

以下头文件必须包含：

```c
#include <fcntl.h>   // 提供 F_RDLCK, F_WRLCK, F_UNLCK 等常量
#include <unistd.h>  // 提供 fcntl 接口
```

常用的 fcntl 命令如下：

```c
F_SETLK   // 不阻塞尝试设置锁，若失败立即返回错误
F_SETLKW  // 阻塞直到获得锁
F_GETLK   // 查看是否已有冲突锁，不改变锁
```

## 三、锁操作函数封装示例

### 1. 加写锁（阻塞式）

```c
#include <fcntl.h>
#include <unistd.h>
#include <errno.h>

int lock_file_write(int fd, off_t start, off_t len) {
    struct flock lock;
    lock.l_type = F_WRLCK;      // 写锁
    lock.l_whence = SEEK_SET;
    lock.l_start = start;
    lock.l_len = len;
    lock.l_pid = 0;

    if (fcntl(fd, F_SETLKW, &lock) == -1) {
        perror("Failed to get write lock");
        return -1;
    }
    return 0;
}
```

### 2. 加读锁（阻塞式）

```c
int lock_file_read(int fd, off_t start, off_t len) {
    struct flock lock;
    lock.l_type = F_RDLCK;      // 读锁
    lock.l_whence = SEEK_SET;
    lock.l_start = start;
    lock.l_len = len;
    lock.l_pid = 0;

    if (fcntl(fd, F_SETLKW, &lock) == -1) {
        perror("Failed to get read lock");
        return -1;
    }
    return 0;
}
```

### 3. 解锁

```c
int unlock_file(int fd, off_t start, off_t len) {
    struct flock lock;
    lock.l_type = F_UNLCK;      // 解锁
    lock.l_whence = SEEK_SET;
    lock.l_start = start;
    lock.l_len = len;
    lock.l_pid = 0;

    if (fcntl(fd, F_SETLK, &lock) == -1) {
        perror("Failed to unlock file");
        return -1;
    }
    return 0;
}
```

### 4. 查询是否已有锁（非阻塞）

```c
int check_lock(int fd, short lock_type, off_t start, off_t len) {
    struct flock lock;
    lock.l_type = lock_type;
    lock.l_whence = SEEK_SET;
    lock.l_start = start;
    lock.l_len = len;

    if (fcntl(fd, F_GETLK, &lock) == -1) {
        perror("Failed to check lock status");
        return -1;
    }

    if (lock.l_type == F_UNLCK)
        printf("File region is unlocked.\n");
    else
        printf("Locked by process %d\n", lock.l_pid);

    return 0;
}
```

## 四、完整应用示例：带锁操作的多进程写入日志

### 主程序逻辑

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <time.h>
#include <string.h>

#define LOG_FILE "log.txt"
#define WRITE_BUF_SIZE 128

int main() {
    int fd = open(LOG_FILE, O_RDWR | O_CREAT, 0644);
    if (fd == -1) {
        perror("open");
        return -1;
    }

    // 获取整个文件的写锁
    if (lock_file_write(fd, 0, 0) != 0) {
        close(fd);
        return -1;
    }

    char buf[WRITE_BUF_SIZE];
    time_t now = time(NULL);
    struct tm *tm_now = localtime(&now);
    snprintf(buf, sizeof(buf), "[%04d-%02d-%02d %02d:%02d:%02d] Process %d started logging.\n",
             tm_now->tm_year + 1900, tm_now->tm_mon + 1, tm_now->tm_mday,
             tm_now->tm_hour, tm_now->tm_min, tm_now->tm_sec, getpid());

    lseek(fd, 0, SEEK_END);  // 移动至文件末尾
    write(fd, buf, strlen(buf));

    unlock_file(fd, 0, 0);   // 释放锁
    close(fd);

    return 0;
}
```

运行多个实例时，可以看到所有写入操作都顺序完成，避免了并发导致的日志混乱。

## 五、常见问题与注意事项

| 问题 | 建议解决方案 |
|------|---------------|
| 跨越 EOF 进行加锁？ | 是合法的，Linux 允许这样提前“预占”空间 |
| 同一个进程能否多次加锁？ | 是的，但需注意解锁次数匹配 |
| 进程关闭后锁会自动释放吗？ | 是的。锁与文件描述符绑定，进程退出后自动释放 |
| 锁是否继承到子进程中？ | 不继承。子进程中需要重新申请 |
| 如何处理死锁？ | 多个进程以不同顺序获取锁时可能死锁，应严格统一顺序 |
| 支持线程安全吗？ | 文件锁属于进程级保护，线程间共享同一 FD，无法区分线程 |

## 六、扩展功能建议

1. **实现一个简单的分布式锁机制**：
   使用临时文件加写锁的方式实现伪分布式锁（如 `/tmp/.lock`）。

2. **使用 flock(2) 简化接口**：
   ```c
   int flock(int fd, int operation);
   ```
   提供更简单的整文件加锁方式，适合粗粒度控制。

3. **配合 mmap 进行共享内存保护**：
   在共享内存区域之上加上锁机制，确保并发修改的安全性。
